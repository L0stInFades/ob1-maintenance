# 逆向正确性复核

2026-09-17（北京时间）复核结论：**本机 OB1 0.1.725 的完整内嵌 JavaScript 已准确提取；格式化代码的规范化 AST 与原载荷一致；重打包程序在已测场景中与原程序一致。** 这些证据支持继续维护这个客户端基线，但不能换算成“全部功能恢复率 99%/100%”。

本次没有修改产品代码 `src/ob1.cjs`，修正的是恢复工具的环境变量索引。原安装的 29 个程序/附带文件仍与快照一致，没有使用原账户、密钥或历史记录进行测试。

其中“可读版”直接由本机 Node 26.8.1 执行；原版和重建版使用内嵌 Node 24.16.0。跨运行时的已测结果也一致，但没有因此宣称所有 Node 版本兼容。

### 行为场景

- help、MCP/extensions/skills/hooks 帮助；未知参数、冲突参数、非法输出格式。
- text/json/stream-json 回复；stdin 与 prompt 合并。
- 中文和空格路径、Unicode 内容、读取分页；实际创建文件、替换、再次读取和文件内容核对。
- 缺失文件、无效工具参数、未知工具；Shell 的 stdout/stderr 与非零退出码。
- 自定义策略拒绝 Shell，确认目标文件没有被创建；glob 与 grep 搜索。

离线测试模拟的是模型响应，文件和 Shell 工具实际执行；检查实际会话中发回模型的工具结果，不只检查 UI 的“成功”提示。HTTP 测试不使用 `--fake-responses`，由应用自带客户端向本地服务发送真实请求。

### 如实保留的首轮失败

首轮行为证据仍在 [behavior-audit.json](../reports/behavior-audit.json)：63 次运行均与原版一致，但只有 60 次满足全部功能预期。3 次失败均是同一搜索场景没有命中测试文件，原版也同样失败。

原因已定位到测试目录：它位于本维护仓库的 `.work/`，被父 `.gitignore` 忽略；程序选择的 `git grep --untracked` 仍排除这些文件。直接执行同样的 Git 命令没有匹配，系统 grep 能找到两行。将同样的文件和命中预期放进独立的空 Git 仓库后，原版、可读版和重建版 **3/3 通过**，见 [search-audit.json](../reports/search-audit.json)。没有放宽搜索内容的断言，也没有修改产品来让测试通过。

比较时排除了临时用户/工作目录、事件时间、当前会话 ID、明确的耗时统计和 Shell 结果末尾的进程组编号。CLI 比较还排除物理堆栈行号及 Node 的启动提示措辞。退出码、工具名/参数/顺序、token 数量、错误内容、工具返回文本和文件效果仍参与核对。原始 stdout/stderr 和首轮证据均保留。

## 本次发现并修正的索引问题

旧分析器把 `process.env[r]` 中的变量名 `r` 当成环境变量的字面名称，造成 **18 个误报名称**。现在仅把 `process.env.NAME` 和 `process.env["NAME"]` 归入明确名称：**307 个**，见 [environment.json](../reports/environment.json)；另外单独记录 **40 处动态访问**，见 [environment-dynamic.json](../reports/environment-dynamic.json)。这不是“所有运行时环境变量都已解析”，动态名称仍需沿赋值关系分析。

同样，3,777 个打包初始化包装器不等于原厂文件数，3,734 条导出别名不是完整类型恢复；81 份文本是按长度等规则选出的提示词、模板和其他长文本，也不是全部提示词数量。README 已澄清这一点。
